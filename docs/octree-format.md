# octree 形式（tengun-octree/1）

点群を LOD 表示するための自前形式。PotreeConverter 2.x と同じ考え方
（ノードごとに間引いた点を持ち、残りを子ノードに渡す）だが、納品先に
外部バイナリを要求しないよう自前で実装している。

出力は 2 つ。

| ファイル | 内容 |
|---|---|
| `hierarchy.json` 相当（`index.html` の設定に同梱） | ノード一覧とメタ情報 |
| `<id>.bin` | 全ノードの点データを連結したもの |

## 座標の扱い

点群の座標は平面直角座標系の生値（例: 東 -42,000 / 北 -155,500）で、
そのまま float32 にすると mm 単位が丸め落ちて描画が壊れる。

このため次の順で持つ。

1. `origin`（bbox の底面中心）を引いてローカル座標にする
2. `scale`（既定 0.001 = 1mm）で割って int32 に量子化する

復元は `world = value * scale + origin`。

## 点レコード（28 バイト固定）

| 位置 | 型 | 内容 |
|---|---|---|
| 0 | int32 | ローカル東（`* scale`） |
| 4 | int32 | ローカル北 |
| 8 | int32 | ローカル標高 |
| 12 | uint8 × 3 | R, G, B |
| 15 | uint8 | 分類（LAS classification） |
| 16 | uint16 | 反射強度 |
| 18 | uint8 | フラグ。bit0 = deviation 有効、bit1 = deviationAlt 有効 |
| 19 | uint8 | 予約 |
| 20 | float32 | 判定に使う較差 (m)。既定は標高較差 |
| 24 | float32 | 表示用の別方式の較差 (m)。既定は法線方向較差 |

無効な較差は NaN を入れ、フラグのビットを 0 にする。

## ノード

- 名前は Potree 方式。`r` が根、`r0`〜`r7` が子、以降同様に 1 文字ずつ増える
- 親が持つのは「間引いて残した点」、子が残りを受け持つ
- 間引きはノードの立方体を `gridSize`（既定 128）分割した格子で、
  1 セルにつき最初の 1 点だけを親が取る方式
- `pointCount <= leafThreshold`（既定 20,000）になったら葉にして全点を持つ

各ノードが持つ情報。

| 項目 | 内容 |
|---|---|
| `name` | ノード名 |
| `level` | 深さ |
| `pointCount` | 点数 |
| `byteOffset` / `byteSize` | `.bin` 内の位置 |
| `cube` | `[x, y, z, size]` ノードの担当空間（LOD 判定用） |
| `min` / `max` | 実際の点の bbox（描画用） |

## 読み込み方

- **Web サーバ配置（フル版）**: 必要なノードだけ HTTP Range リクエストで取る。
  Range 非対応のサーバなら 1 度だけ全体を取得して以後は切り出す
- **file://（軽量版）**: `.bin` を base64 で HTML に埋め込む。
  file:// では fetch が CORS で止まるため、外部ファイルにはできない

## 設計 TIN（TGND）

設計面は別形式で持つ。

| 位置 | 型 | 内容 |
|---|---|---|
| 0 | uint32 | マジック `0x54474E44`（"TGND"） |
| 4 | uint32 | バージョン（1） |
| 8 | uint32 | 節点数 |
| 12 | uint32 | 三角形数 |
| 16〜 | float32 × 3 × 節点数 | ローカル座標（origin を引いた値） |
| 〜 | uint32 × 3 × 三角形数 | 節点の添字 |
